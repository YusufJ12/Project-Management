# Project Documentation

Project documentation is grouped by purpose. Product and architecture documents describe intended behavior; they are not proof that a feature exists in the current code. Check the application, migrations, configuration, and tests before implementation or deployment.

## Folders

- [`product/`](product/PRD.md) — product requirements and scope.
- [`architecture/`](architecture/ERD.md) — intended entities and relationships.
- [`planning/`](planning/PROJECT_PLAN.md) — technical direction and roadmap.
- [`operations/`](operations/SHARED_HOSTING_GUIDE.md) — deployment and hosting checks.
- [`history/`](history/DEVELOPMENT_LOG.md) — historical progress notes; test results and status must be re-verified.

Keep repository-wide agent instructions in the root `AGENTS.md`, the application overview in the root `README.md`, and Flutter-specific instructions in `mobile/README.md`.
